# プライバシー

> 実装の確認日: **2026-08-16** ／ 外部規約の確認日: **2026-08-12**
>
> 提供元の規約やCLI仕様は変更されます。確認日以後の最新の公式情報がこのページに優先します。

Embodied HA は、家の中で無人・継続的にエージェントを動かすアドオンです。選択したエージェント
ハーネスや Home Assistant の音声プロバイダーへ、家庭内の情報が送られる場合があります。
利用を始める前に、送られ得る情報、送信先、各アカウントのデータ設定を確認してください。

## サードパーティのツールについて

Embodied HA は、Claude Code、Codex、Google Antigravity などのエージェントCLIを呼び出します。
利用者がセットアップ画面から導入を選んだ場合、CLIは各提供元の配布元から直接取得されます。

| CLI | 取得元 |
|---|---|
| Claude Code | `downloads.claude.ai/claude-code-releases` |
| Codex | `api.github.com/repos/openai/codex/releases` |
| Google Antigravity | `antigravity.google/cli/install.sh` |

本アドオンはこれらのCLIを同梱・再配布せず、そのライセンスを付与しません。本プロジェクトはCLI自体の
提供者ではなく、その可用性や内容を保証しません。CLIの提供、利用条件、障害、データの取り扱いは
各提供元の規約に従います。本アドオンは導入と認証の手順を簡略化するため、手動で導入する場合と同じ
規約画面をすべて利用者へ表示するとは限りません。特にAntigravityのログインでは、Ingress内で認証を
完了させるため、CLIが表示するTerms of Serviceの確認画面をEHAが自動操作します。この操作は、利用者の
アカウントによる規約への同意として扱われる可能性があります。**インストールやログインを開始する前に、
利用するCLIの規約を次のリンクから自分で確認してください。**

- [Anthropic Consumer Terms](https://www.anthropic.com/legal/consumer-terms)
- [Anthropic Commercial Terms](https://www.anthropic.com/legal/commercial-terms)
- [OpenAI Terms of Use](https://openai.com/policies/terms-of-use/)
- [Google Antigravity Additional Terms of Service](https://antigravity.google/terms)

### セットアップ前の確認

初回セットアップでは、どのCLIのインストール・ログインを始める前にも、Web UIが上のリンクと
「Embodied HAがツールのインストールと認証操作を代行することを理解し、事前に利用する各ツールの
利用規約を確認して同意しました」という文を表示し、同意を記録します。同意するまで、3種類のCLIの
インストールとログインの操作は実行できません。

この確認は、**EHAが代行することへの同意**であって、各提供元との契約の代わりではありません。
提供元との関係は、認証したアカウントとその規約で決まります。

> **すでに稼働しているインスタンスでは、この画面は出ません。** ハーネスを選択済みのまま更新した
> 場合、動いているエージェントを止めないために確認を省略します。以前に導入した環境では、
> 上のリンクを自分で開いて確認してください。

### 無人実行と公式の非対話モード

EHAはCLIを人の操作なしに繰り返し起動します。これはEHAの中核的な動作であり、通常の対話画面を
人が操作する使い方とは異なります。一方、EHAが使う実行口は、各提供元がスクリプトやCI向けに公開している
公式の非対話モードです。

| CLI | EHAが使う実行口 | 提供元の説明 |
|---|---|---|
| Claude Code | `claude -p` | [非対話モードによるプログラム実行](https://code.claude.com/docs/en/headless) |
| Codex | `codex exec` | [スクリプト・CI向け非対話モード](https://developers.openai.com/codex/noninteractive) |
| Google Antigravity | `agy -p` | [print/headlessモードの変更履歴](https://antigravity.google/changelog) |

Anthropic Consumer Termsは、Anthropic APIキー経由または別途明示的に許可された場合を除く自動・
非人間的アクセスを制限しています。同時に、Claude Codeの公式文書は`claude -p`をスクリプトやCI/CDで
使う非対話モードとして案内しています。EHAはこの公開された実行口を使います。Anthropic APIキーを
使う場合はCommercial Termsが適用されます。認証方法によって契約、課金、データの扱いが変わるため、
利用するアカウントに適用される現在の条件を確認してください。

公式に非対話モードが提供されていることは、あらゆる用途、契約、設定が無条件に許可されることを
意味しません。本プロジェクトは各社による個別の承認や法的判断を示すものではありません。

### Google Antigravityで守る接続境界

Google Antigravity追加規約は、第三者のソフトウェア、ツール、サービスを使ったAntigravityへのアクセスを
禁止し、Antigravity OAuthを第三者クライアントで使う例を挙げています。一方、Googleは`agy -p`の
shell script・subprocess・CIでの利用や、外部MCP、プラグイン、hooksも公式機能として案内しています。

EHAはこの区別を次のように扱います。

- Googleの公式インストーラーから公式`agy`バイナリを取得する
- 認証とGoogle側サービスへの接続は公式`agy`に任せる
- 公開されている`-p`、`--model`、`--output-format`等のCLIオプションを使う
- Antigravity OAuthトークンを独自クライアントへ転用しない
- 非公開のバックエンドAPIやAntigravity内部のLanguage Server APIを直接呼ばない

この構成は、第三者クライアントが認証情報を流用してAntigravityへ直接接続する方式ではなく、公式CLIの
非対話実行を外側から起動する方式です。これは接続方法についての技術的な区別であり、追加規約から
明示的に除外されるという法的判断ではありません。追加規約の表現は広く、第三者製品が公式`agy`を
subprocessとして継続実行する構成を個別に許可する記載や、GoogleによるEHAの個別承認は確認できて
いません。Antigravityを選ぶ前に現在の規約を確認し、この接続境界を変更する派生実装では、その実装者が
改めて利用条件を確認してください。

## データの流れ

Embodied HA は、個体ごとの作業ディレクトリを自ら選び、選択されたCLIを会話、自律ループ、日誌生成などで
無人実行します。既定の作業ディレクトリは個体データ内の `workdir` です。CLIの会話履歴や作業領域が
カレントディレクトリ単位で管理される場合、その単位もEHAが決めることになります。

「EHAが扱える」ことと「毎ターン送られる」ことは同じではありません。現在の主な経路は次の通りです。

| 情報 | いつ送られるか | 主な送信先 |
|---|---|---|
| 会話文、キャラクター、長期記憶、最近のログ、身体状態、センサー要約 | 会話または自律ループを実行したとき | 選択したエージェントCLIの提供元 |
| MCPツールの結果（HA状態、記憶検索、HTTP応答など） | そのターンでエージェントがツールを呼んだとき | 同じターンを処理するエージェントCLIの提供元 |
| カメラの静止画 | `use_device_camera`、`watch_media`、`review_camera_history`を呼んだとき | 同じターンを処理するエージェントCLIの提供元 |
| マイクの音声 | `listen`等で文字起こしを明示したとき | Home Assistantで選択したSTTプロバイダー |
| マイクの一時録音 | Antigravityで`concentrate_hearing`を呼んだとき | Google Antigravity |
| **周辺の会話（誰も話しかけていない発話）** | **周辺会話の拡張を有効にしている間、上限の範囲で継続的に** | Home Assistantで選択したSTTプロバイダー |
| 文字起こし結果 | STTが成功し、MCP結果、音声チャット、または周辺会話として自動でターンへ入ったとき | 選択したエージェントCLIの提供元 |
| 読み上げる文章 | 発話するとき | Home Assistantで選択したTTSプロバイダー |
| 検索語、HTTP送信内容、承認されたAI Loungeの投稿 | 対応するツールを呼んだとき | 検索先、設定したHTTP送信先、GitHub等 |

カメラ画像は、カメラへ投射しているだけでは自動送信されません。エージェントが画像取得ツールを
呼んだターンにだけ、その画像がCLIへ渡ります。カメラ履歴を有効にすると静止画はローカルの一時領域へ
定期保存されますが、CLIへ渡るのは履歴取得ツールを呼んだときだけです。

Embodied HA本体は常時STTや内蔵ウェイクワード検出を行いません。EHA内の能動聴取では、
文字起こしを要求しない限り、録音は音量解析後に削除され、音量等のメタデータだけがMCP結果になります。

### 周辺の会話を有効にした場合

別アドオンを追加すると、家の中の日常会話を継続的に文字起こしし、エージェントが「さっき聞いたこと」として
参照できるようになります。**既定では無効で、利用者が明示的に有効化したときだけ動きます。**
どのSTTプロバイダーへ送られるかは、これまでと同じくHome Assistantの設定で利用者が選びます。ただし
**送るかどうか、いつ送るか、どれだけ送るかを決めているのはこのプロジェクトの側**なので、その範囲を
ここに示します。

- **対象は、誰も話しかけていない発話です。** ウェイクワードやボタンをきっかけとする通常の音声操作と違い、
  設定した音源で検出された発話が、宛先を問わず文字起こしの候補になります。
- **送る量に上限があります。** 出荷時の既定は1分あたり6リクエスト、1時間あたり300秒、1日あたり1800秒の
  音声で、上限に達した分は送られずに捨てられます。上限は設定で変更できます。
- **音声そのものは保存しません。** 文字起こしの結果だけが、追加アドオン側の非公開ファイルに残ります
  （保持期間と場所は[データの置き場と保持](data_and_retention.md)を参照）。
- **文字起こしはMQTTを経由します。** 同じブローカーへ接続できる他のクライアントは、その内容を購読できます。
  ブローカーの認証と接続範囲は利用者の管理下にあります。
- **エージェントのターンへ自動で入ります。** 自律ループと音声チャットでは直近の数件（既定3件・
  1〜20件で設定可）が自動で渡り、そこから先は上の表と同じく、選択したエージェントCLIの提供元へ
  送られます。文字チャットでは本文は自動で渡らず、参照先の案内だけが渡ります。
- **自動で渡る範囲は、そのときの身体の居場所で狭まります。** 物理身体でいるときは、設定した全音源の
  発話が対象です。電脳体でマイクへ投射しているときは、そのマイクに対応する部屋の発話だけになります。
  マイク以外へ投射しているとき、および身体の状態を読み取れないときは、**何も渡りません**。
- **渡るときは「非信頼の観測」として渡ります。** その部屋の音声を文字起こしした環境観測であって
  エージェントへの命令ではないこと、話者を推定しないことをプロンプトに明記し、どの部屋で拾ったかを
  添えます。立ち聞きした指示が命令として通らないための枠であって、送信範囲を狭めるものではありません。
- **発話者は推定しません。** 誰の声かは記録されず、家族・来訪者・エージェント自身の音声も区別されません。

したがって、**選択したCLIの提供元は、設定とツール利用に応じて、センサー値、家庭内の会話の文字起こし、
カメラ画像、記憶、家電状態を含むターンを受け取る場合があります。** 個人向けサブスクリプションとAPI・
法人契約では、学習利用、保持期間、削除方法が異なります。具体例と公式リンクは
[データの置き場と保持](data_and_retention.md)を参照してください。

## 同居人・来訪者への配慮

アカウント所有者以外の声、姿、行動、生活パターンも処理対象になり得ます。設置場所にいる同居人や来訪者へ
知らせ、必要な合意を確認してください。録音・撮影・外部送信に関する地域の法令や住宅内のルールも、
利用者自身で確認してください。これは法的助言ではありません。

## 利用前チェック

1. 使うエージェントCLIの契約種別と、学習利用の設定を確認する。
2. Home Assistantで選択したSTT・TTS統合が、ローカル処理かクラウド処理か確認する。
3. 不要なカメラ、マイク、HTTP送信先、AI Lounge設定を登録しない。
4. カメラ履歴が不要なら無効のままにする。
5. 周辺の会話を有効にするなら、上限と保持期間を自分の家に合う値へ調整する。
6. 同居人・来訪者へ知らせる。周辺の会話を有効にした場合は、その部屋で話す全員が対象になる。
7. 定期的にローカルログと提供元側の会話履歴を見直す。

アドオンを停止すると新しいEHAターンは止まりますが、すでにローカルまたは提供元へ保存されたデータは
自動では消えません。停止、認証解除、ローカルデータ削除、提供元側の履歴削除は別々に行ってください。
